# CONTRIBUTING

Спасибо, что хотите улучшить платформу! Этот файл описывает процесс внесения изменений и требования к ним. Формат файлов резюме подробно разобран в [README.md](README.md).

## Процесс
1. Сделайте fork репозитория и создайте ветку от `main`.
2. Внесите изменения и проверьте локальную сборку (команды ниже).
3. Откройте Pull Request в `main`.

### Что произойдёт в PR
* Сработает `validate.yml`: если менялись `.typ`-файлы или `build.py` — пересоберётся всё, если только `users/*.yaml` — только изменённые файлы.
* PDF-артефакты прикрепятся к прогону CI, а результат появится комментарием в PR.
* ⚠️ Файлы `*.py` и `*.typ` закреплены за `@SlavaBuchnev` через `CODEOWNERS` — такие PR требуют его ревью.

## Как изменить своё резюме
1. Отредактируйте (или создайте) один файл `users/{фио}.yaml` — формат см. в README.
2. Проверьте локально:
   ```bash
   python3 build.py build --filter users/{фио}.yaml
   ```
3. Если сборка падает — читайте сообщение: валидатор (`tools/schema.typ`) пишет на русском и указывает точный путь до ошибки.

Обязательные правила (иначе сборка упадёт):
* Только пробелы для отступов (без Tab); строки с `@` или `+` — в кавычках; `???` в обязательных полях запрещён.
* Набор имён блоков (`blocks`) одинаковый во всех языках; каждый блок использован хотя бы в одном шаблоне.
* Публичность: телефон, почта и другие контакты попадут в публичные PDF на GitHub Pages — коммитьте только то, что можно раскрывать.

## Как добавить новый шаблон (для мейнтейнера)
1. Создайте папку `templates/your-template-name/` с файлами:
   * `settings.typ` — стили (шрифты, цвета, отступы);
   * `template.typ` — макет с обязательной функцией `resume(data)`.
2. Функция `resume(data)` принимает словарь с ключами:
   * `meta` — `lang`, `name`, `title`, `contacts` (массив строк);
   * `center`, `left`, `right` — массивы блоков `{type, title, data}` в порядке раскладки.
3. Поддержите все типы блоков из `tools/schema.typ` через словарь рендеров, как в существующих шаблонах:
   массивные `experience`, `projects`, `education`, `awards`, `skills` и строковые `text`, `portfolio`.
4. Зарегистрируйте шаблон в `tools/router.typ` — импорт и запись в словарь `templates`.
5. Проверьте: `python3 build.py build` — все существующие резюме должны собраться без изменений,
   а файл `users/example.yaml` должен корректно отрендериться в новом шаблоне (добавьте его в `templates:` примера, если хотите демонстрацию на сайте).

## Соглашения по коду
* Документация, комментарии и сообщения об ошибках — **на русском**.
* `build.py` — только стандартная библиотека Python (никаких зависимостей, кодировка UTF-8, пути через `pathlib`).
* Вся валидация данных — в `tools/schema.typ`; ошибки должны быть понятны человеку, который впервые открыл YAML-файл.
* Сайт (`web/`) — ванильный HTML/CSS/JS без сборщиков и фреймворков.
* Перед PR прогоняйте `python3 build.py build` — это полный «тест» проекта.

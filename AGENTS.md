# AGENTS.md — Руководство для AI-агентов

## Обзор проекта

Платформа для создания и автоматической публикации PDF-резюме. Дизайн (шаблоны Typst) отделён от контента (YAML-файлы пользователей). Контент каждого пользователя живёт в одном файле `users/{фио}.yaml`: секции языков (`ru:`, `en:`) с именованными блоками + ключ `templates:` с раскладкой блоков по колонкам для каждого шаблона. Один и тот же контент рендерится в разные шаблоны и языки без дублирования. Собранный сайт с PDF публикуется на GitHub Pages.

- Репозиторий: `github.com/SlavaBuchnev/Resume` (публичный, ветка по умолчанию — `main`).
- Лицензия: MIT.

## Технологический стек

- **Typst** (компилятор в PDF, в CI ставится через `typst-community/setup-typst@v3`; локально проверено на 0.15.1) — шаблоны, верстка и валидация данных.
- **Python 3** (только стандартная библиотека) — скрипт сборки `build.py`. Файлов `pyproject.toml`, `requirements.txt` нет, сторонние пакеты запрещены. YAML из Python не парсится — список шаблонов/языков получается через `typst eval` (см. `tools/list.typ`).
- **Vanilla HTML/CSS/JS** — статический сайт-визитка (`web/`), без фреймворков и сборщиков. `package.json` нет.
- **GitHub Actions** — CI/CD (`.github/workflows/`).

## Структура и архитектура

```text
├── tools/                # Весь код на Typst (компиляция и валидация)
│   ├── main.typ          # Точка входа: читает sys.inputs (data, template, lang),
│   │                     # валидирует YAML, выбирает язык/раскладку и рендерит
│   ├── schema.typ        # Схемы данных и валидатор. Ошибки → panic с сообщением на русском
│   ├── router.typ        # Коммутатор шаблонов: словарь имя → функция resume(data)
│   └── list.typ          # Служебный файл для build.py: metadata(<resume-config>) со
│                         # списком языков и шаблонов файла пользователя
├── templates/            # Шаблоны верстки
│   ├── google-classic/   # settings.typ (стили) + template.typ (макет)
│   └── harvard/          # та же структура
├── users/                # Контент резюме: один файл {фио}.yaml на человека
│   ├── example.yaml      # Демонстрационный файл (образец для заполнения)
│   └── v.s.buchnev.yaml  # Резюме владельца
├── build.py              # Сборка: обход users/*.yaml, typst eval для списка шаблонов,
│                         # вызов typst compile, генерация _site/
├── web/                  # Статический сайт: index.html + app.js + style.css
│                         # app.js подгружает resumes.json и строит кнопки скачивания PDF
├── _site/                # Артефакт сборки (в .gitignore). Пересоздаётся с нуля
│                         # каждым запуском build.py. Не редактировать вручную
└── .github/workflows/    # deploy.yml (push в main → GitHub Pages), validate.yml (PR → проверка сборки)
```

Поток сборки одного резюме: `build.py` находит `users/{user}.yaml` → `typst eval 'query(<resume-config>)' --in tools/list.typ`
возвращает список шаблонов и языков файла → для каждой пары вызывается
`typst compile tools/main.typ --root . --input data=/users/{user}.yaml --input template=<template> --input lang=<lang>` →
`tools/main.typ` парсит YAML (`yaml(data_path)`), валидирует (`schema.typ`: языки, блоки, раскладки),
выбирает секцию языка и раскладку шаблона (`select-resume`), получает рендерер
(`router.typ`) и вызывает `resume(data)`. Затем `build.py` кладёт PDF в `_site/{user}/resume_{template}_{lang}.pdf`,
генерирует `_site/resumes.json` (группировка по пользователям) и копирует `web/` в `_site`.

Данные, которые шаблон получает на вход (результат `select-resume`):
словарь с ключами `meta` (lang, name, title, contacts), `center`, `left`, `right`
(массивы типизированных блоков `{type, title, data}`).

Формат `users/{фио}.yaml`:
- Секции языков верхнего уровня (любые имена, напр. `ru:`, `en:`), внутри каждой: `name`, `title`,
  `contacts` (массив строк) и `blocks` — словарь имя → `{type, title, data}`.
  Набор имён блоков обязан совпадать во всех языках.
- `templates:` — словарь имя-шаблона → раскладка: словарь колонок `center`/`left`/`right`
  со списками имён блоков. Явная раскладка обязательна; каждый блок должен использоваться
  хотя бы в одном шаблоне, иначе panic (защита от опечаток).

## Команды сборки и проверки

Требуется `typst` в PATH и Python 3.

```bash
# Собрать все PDF и сайт в _site/
python3 build.py build

# Собрать только указанные файлы пользователей (используется CI на PR)
python3 build.py build --filter users/v.s.buchnev.yaml

# Ручная компиляция одного PDF (минуя build.py).
# Без --input lang/template возьмутся первые из файла.
# Путь в data — root-absolute (с ведущим /), т.к. main.typ лежит в tools/.
typst compile tools/main.typ output.pdf --root . \
  --input data="/users/v.s.buchnev.yaml" \
  --input template="google-classic" \
  --input lang="ru"
```

Запуск локального сервера для просмотра `_site/`: `cd _site && python3 -m http.server 8000`.

## Тестирование

Автоматических тестов нет (ни pytest, ни аналогов). Стратегия проверки:

1. **Валидация в Typst** — `tools/schema.typ` вызывает `panic` с русскоязычным сообщением при любой
   ошибке в YAML (неизвестные/пропущенные поля, неверные типы, пустые `???`-значения,
   неизвестный блок в раскладке, блок не использован ни в одном шаблоне, разный набор
   блоков у языков). Падающая компиляция = непройденный тест.
2. **CI `validate.yml`** на Pull Request в `main`: если менялись `.typ` или `build.py` —
   пересобирается всё, если только `users/*.yaml` — только изменённые файлы (`--filter`).
   PDF-артефакты прикладываются к прогону, результат пишется комментарием в PR.
3. Локально достаточно прогнать `python3 build.py build` — он упадёт с понятной ошибкой,
   если какой-то YAML или шаблон сломан.

## Соглашения по коду и данным

- Вся документация, комментарии и сообщения об ошибках — **на русском**. Новый код следует
  этому же стилю (см. `tools/schema.typ`, `build.py`). Процесс внесения изменений — в `CONTRIBUTING.md`.
- Один файл на человека: `users/{фио}.yaml` (ФИО в нижнем регистре через точки, напр.
  `v.s.buchnev.yaml`). Старый формат папок `users/{фио}/` и расширение `.yml` не
  поддерживаются — `build.py` предупреждает и пропускает такие записи.
- YAML-файлы: только пробелы для отступов (без Tab), строки с `@` или `+` — в кавычках,
  текст `???` в обязательных полях запрещён (сборка намеренно падает).
- Имена блоков в `blocks` — идентификаторы, общие для всех языков; заголовки (`title`)
  лежат внутри каждого языка. Порядок имён в раскладке `templates:` задаёт порядок
  блоков в PDF; один блок нельзя указать дважды в одном шаблоне.
- Типы блоков с `data`-массивом: `experience`, `projects`, `education`, `awards`, `skills`
  (схемы полей — в `tools/schema.typ`); типы со строкой: `text`, `portfolio`.
- **Новый шаблон** (для мейнтейнера): папка `templates/{name}/` с `settings.typ` и `template.typ`;
  в `template.typ` обязательна функция `resume(data)`, принимающая `meta`, `center`, `left`, `right`;
  затем импорт и запись в словарь `templates` в `tools/router.typ`. Каждый шаблон должен поддерживать
  все типы блоков из `tools/schema.typ` (словарь `renderers`).
- Python в `build.py` — стандартная библиотека, кодировка UTF-8, пути через `pathlib`.
  Typst вызывается с `--root .`; пути к данным передаются как root-absolute (`/users/...`),
  потому что `yaml()` резолвит относительные пути от файла, а не от корня.
- `*.py` и `*.typ` закреплены за `@SlavaBuchnev` (`.github/CODEOWNERS`) — их правки требуют его ревью.

## CI/CD и деплой

- **Push в `main`** → `.github/workflows/deploy.yml`: `python build.py build`, публикация `_site/`
  на GitHub Pages (permissions: pages + id-token). Сайт: `slavabuchnev.github.io/Resume`.
- **Pull Request в `main`** → `.github/workflows/validate.yml`: типизированная сборка
  (всё / только изменённые `users/*.yaml`), артефакты PDF, комментарий в PR.

## Замечания по безопасности

- Репозиторий и GitHub Pages — публичные. Контакты из YAML (телефон, почта, Telegram) попадают
  в публично доступные PDF — коммитить только те данные, которые допустимо раскрывать.
- Секретов и приватных ключей в репозитории нет и не требуется (токены Pages выдаются GitHub Actions).
- Пользовательский YAML интерпретируется Typst как разметка: содержимое `data` вставляется
  в документ, экранирование спецсимволов Typst в контенте не предусмотрено.

## Известные ограничения

- `_site/` в рабочей копии пересоздаётся каждой сборкой — это не источник правок.
- Новые шаблоны, не добавленные в `tools/router.typ`, собрать нельзя — упадёт
  с panic «Неизвестный шаблон».
- `typst query` как отдельная подкоманда deprecated начиная с Typst 0.15 — `build.py`
  использует `typst eval 'query(<resume-config>)'`.
